# 인수인계

> 2026-10-23 변경: 아래 초기 정확 모델 검색 설명은 [단계별 모델 범위 계약](MODEL_SCOPE.md)으로 보완된다. 최신 실행 범위·배포 의존성은 해당 문서를 우선한다.

기준일: 2026-10-21. 최신 팀 규약은 `MRO Agent 팀 인터페이스 규약 v0.1 (3).pdf`의 본문 **v0.3**입니다. 현재 작업은 **DB 구성과 읽기 전용 MCP 구축**이며 LLM2·LLM3 구현은 보류합니다. [작업 규칙](../AGENTS.md), [작업 계획](WORK_PLAN.md), [팀 연결 계약](INTEGRATION_CONTRACT.md)을 따릅니다. 신구 규약의 변경과 미해결 충돌은 [검토 보고서](../reports/team-interface-v03-review.md)에 있습니다.

## 목표와 담당

Airbus 자연어 정비 신고를 같은 항공사·정확한 모델의 과거 근거와 연결해 부서 배정을 지원합니다. 필수 범위는 SDR·AMM 참조·JASC DB, 조회 함수, 근거 원문 조회, 나현님과의 R01·R02·R03·R05 MCP 통합, 재구축 가능한 마이그레이션·적재 패키지입니다. 실제 정비 절차 수행이나 운항 허가를 결정하지 않습니다.

영호님은 Backend·공유 DB 생성/마이그레이션/계정/전체 데이터 복원·저장·배정, 나현님은 MCP 클라이언트·business-mcp 연결, 경님은 기체·수리이력 목업 담당입니다. 최신 규약에서는 AI 서버가 LLM1~3·라우팅·완료 전 근거 검증을 맡습니다. 현재 사용자 범위에 따라 LLM2/3 구현은 시작하지 않습니다. R04 담당은 미정이며 R06 색인 갱신은 MCP에서 제외합니다.

## 업무 흐름

[전체 흐름](process.mmd)은 사용자가 제시한 아키텍처와 팀 PDF의 접수 규칙을 따릅니다.

- 접수 단계 필수정보 누락·기체/항공사/모델 충돌은 **422 보완 안내**입니다. 요청 레코드와 AI 작업을 만들기 전에 응답하고, 사용자가 수정 후 다시 제출합니다. 이 단계에서 사람 검토로 보내지 않습니다.
- 검증 통과 후 `QUEUED → CLASSIFYING`. 동일 기체 이력 연결이 충분하면 AI 실행기가 B02 근거를 검증하고 COMPLETED/ASSIGN 이벤트를 보내며 Backend가 배정을 실행합니다. 조사 경로도 AI가 B02/R05 검증 후 완료 이벤트를 보냅니다.
- 부족하면 `INVESTIGATING → REVIEWING`으로 진행하며 보완은 한도 내 재조사합니다. 조사 이후 불확실성·한도 초과 등은 사람 검토로 인계합니다.
- 실제 정비팀 거절은 사람 검토로 인계하고 자동 재배정을 중단합니다. 수락은 정비 완료가 아닙니다.
- 조회 중 `NEEDS_INPUT`은 도구 결과이며 접수 반려나 상태 변경을 수행하지 않습니다.
- 사용자 결정에 따라 MCP는 팀 PDF 기준으로 읽기 전용입니다. 로컬 카탈로그에서 B04·B05·B06·R06을 제거했습니다. 요청 권한·검색 범위와 근거 ID는 Google 명세를 따릅니다.

## 데이터 한계

원본 패키지는 `data/source/airbus-mcp-data-v1/`입니다. 이번 건수·필드·연결·해시 검사는 [원본 점검](../reports/design-data-profile.json), 변환 기준은 [데이터 매핑](DATA_MAPPING.md)을 참조합니다.

- 원본 SDR은 76개 컬럼입니다. 정제 JSONL은 원본 전체 필드를 개별 보존하지 않으므로, 원본 `raw` 객체와 정제 payload를 함께 보존하는 설계입니다.
- AMM은 SDR에서 규칙으로 추출한 참조번호·인용 맥락입니다. 실제 AMM 절차 본문이 아니며 의미 검토는 `not_reviewed`, 실제 적용성은 `not_verified`입니다.
- 모델의 `exact_label`은 정제 기준상 상세 표기입니다. `model_certification_verified=false`를 실제 모델 인증 완료로 바꾸지 않습니다.
- pgvector 임베딩·실제 벡터 검색은 구현했습니다. Airbus 기술자료 본문은 포함하지 않습니다.
- 원본 SDR과 파생 AMM은 같은 `evidence_group_id`입니다. 독립 근거 두 개로 세지 않습니다.
- 평가용 SDR과 파생물은 검색 DB에서 제외합니다. 목업 신고·부서 정답은 독립 검색 평가 정답이 아닙니다.
- 기존 업무 목업은 실제 기체 이력·조직이 아닙니다. 팀 시드와 ID·규모가 다르므로 그대로 공통 업무 테이블에 적재하지 않습니다.
- 기존 29개 검사와 이번 설계용 점검은 데이터 무결성 검사입니다. 검색 품질·진단 정확도·PostgreSQL 구축 성공을 뜻하지 않습니다.
- JASC는 필수 DB·MCP 범위입니다. 검색 후보이며 AMM 번호·ATA·부서와 자동 변환하지 않습니다.

## 보존과 재현

Google 원문 보존본·팀 PDF·전체 원본 패키지는 로컬 별도 자료입니다. Git에는 구현 코드·계약·관측 목록·검증 결과를 포함합니다. 데이터 패키지 contracts에는 수정 전 카탈로그가 보존되어 있습니다. 전체 데이터 실행에는 별도 패키지가 필요하며 합성 테스트는 패키지 없이 재현됩니다.

관계형·벡터 DB와 읽기 전용 MCP를 구현했습니다. [실행 안내](RUNBOOK.md), [Backend Flyway 통합 자료](../integration/backend/README.md), [검증 결과](../reports/implementation-review.md)를 사용합니다. 팀 애플리케이션 연결은 남아 있습니다.

전체 데이터 전달본은 로컬 `artifacts/handoff/mro-rag-handoff-20261021-v1.zip`입니다. 스키마 호환 data-only dump(9개 데이터 테이블)·manifest·체크섬·verify.sql을 포함하며, 런타임 rag_request_contexts는 제외합니다. Backend가 Flyway 적용 후 `scripts/rag-restore.sh`로 복원합니다. 우리 ingest/embed/Alembic은 격리 로컬 제작·검증용이며 공유 DB에서 실행하지 않습니다. 기존 전달 파일은 이번 규약 갱신에서 변경하지 않았습니다.
