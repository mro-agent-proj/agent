# JASC DB·MCP 필수 작업 기준

갱신: 2026-10-21. 사용자가 JASC 코드표의 DB 적재와 MCP 조회를 우리 필수 담당 범위로 확정했습니다. 구현 진행 상태는 [작업 계획](WORK_PLAN.md)을 따릅니다.

## 준비된 것과 남은 것

- 준비: `data/source/airbus-mcp-data-v1/reference/jasc_codes.jsonl`의 548개 코드, 기존 SQLite 데이터, R01 입출력 명세.
- 남음: PostgreSQL 적재, 조회 함수, 팀 `rag-mcp` 서버 연결, 실제 DB를 사용하는 통합 검증.
- PostgreSQL은 팀의 Flyway·별도 RAG 적재 절차에 포함합니다. JASC 테이블과 데이터가 빈 DB 재구축 과정에서도 함께 생성·적재되어야 합니다.
- 벡터 DB 선택과 무관하게 JASC 작업은 진행할 수 있습니다. 초기 분류 LLM의 도구 권한이나 전체 업무 상태 흐름은 바꾸지 않습니다.

## DB 적재

코드를 문자열로 저장하고 명칭·정의·코드표 버전·출처를 보존합니다. 명칭과 정의가 다른 공식 자료에서 왔다면 각각의 출처도 보존합니다. 버전별 중복 방지와 활성 버전 선택은 팀 DB 설계·마이그레이션에 맞춰 구현합니다.

548개는 공식 코드표 두 자료를 합친 현재 패키지 범위입니다. 최신 공식 단일 표의 전체 개수라는 뜻이 아닙니다. 정의가 없는 61개 코드는 null을 보존합니다. 2924는 공식 명칭을 찾지 못한 코드 표시 상태를 보존하며 명칭을 임의 생성하지 않습니다.

JASC는 공통 코드표입니다. 항공사·모델별로 복제하거나, 특정 항공사 SDR에서 출현한 코드만으로 사전을 제한하지 않습니다. 요청 권한과 context_version 검증은 기존 연결 계약을 따릅니다.

## 조회와 MCP

| 항목 | 필수 동작 |
|---|---|
| 서버·도구 | `rag-mcp`의 R01 `search_jasc_codes` |
| 입력 | 기존 계약의 `request_id`, `context_version`, `query` 또는 `codes`, 선택 `limit` |
| 코드 조회 | 저장된 코드에 대한 정확 조회 |
| 텍스트 조회 | 명칭·정의 검색. 한국어 질의는 실제 영어 자료로 별도 검증 |
| 반환 | 코드, 명칭, 정의, 출처 URL, 코드표 버전. 원문 정의가 없으면 null |
| 오류·빈 결과 | 미존재 코드의 `INVALID_JASC`와 키워드 결과 없음의 `NO_MATCH` 구분 |
| 사용 역할 | 조사·판정 및 검토·배정 LLM |
| 후속 활용 | SDR·AMM 검색 후보로 전달. 확정 원인·AMM·ATA·부서 정답으로 자동 변환하지 않음 |

## 완료 기준과 산출물

1. 팀 마이그레이션·시드로 현재 548개 코드를 PostgreSQL에 적재하고 같은 버전을 다시 실행해도 중복이 없습니다.
2. 원본과 코드·명칭·정의·버전·출처가 일치하며 null·명칭 미확인 상태를 보존합니다.
3. 알려진 코드와 키워드 검색이 실제 DB에서 동작하고, 미존재 코드·검색 결과 없음·권한/버전 오류를 구분합니다.
4. 팀 MCP 서버에서 R01을 호출해 명세에 맞는 응답을 받습니다. 정적인 샘플 응답만으로 완료 처리하지 않습니다.
5. 조사·검토 LLM이 반환 코드를 후속 SDR·AMM 조회 후보로 사용할 수 있고, 원래의 항공사·정확한 모델 범위와 사용자 고정 조건은 유지됩니다.

산출물은 JASC 테이블 마이그레이션, 시드·적재 코드, 조회 함수, R01 MCP 어댑터, 호출 예제, 통합 검증 결과입니다. PostgreSQL 548개 적재와 R01 HTTP MCP 구현·테스트를 완료했습니다. Backend 위임 컨텍스트 연결은 별도입니다.
