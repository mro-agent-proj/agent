# DB·MCP 구현 검토 · 2026-10-21

검토 범위는 이 저장소의 RAG DB·오프라인 적재·임베딩·읽기 전용 MCP입니다. LLM2/LLM3, business-mcp, RabbitMQ 실행기와 Backend 배정 처리 전체는 포함하지 않습니다.

실측은 [runtime-verification.json](runtime-verification.json), 원본 점검은 [design-data-profile.json](design-data-profile.json)에 있습니다. 0.533초/0.239초는 로컬 MPS에서 모델 로딩 후 검색+R05 세 건을 수행한 단발 측정이며 성능 보장이나 부하 테스트가 아닙니다. 검색 결과의 관련성·진단 정확도 평가는 별도입니다.

## 검토에서 보완한 사항

- 같은 AMM 번호의 서로 다른 근거와 부모 SDR를 복합 FK로 구분했습니다.
- reported_action의 원본 trim 규칙과 오프셋 차이를 확인해 원문·좌표 보존 방식으로 검증했습니다.
- 요청 컨텍스트를 재게시하며 이전 버전으로 되돌리는 문제를 막고 새 버전에서 기존 실행을 철회하도록 했습니다.
- 검색 설정이 여러 개일 때 임의 선택하지 않고 Backend가 index_keys를 지정하도록 했습니다.
- 모델의 긴 입력을 창으로 처리하고 재토큰화 길이를 검사합니다. 데이터 전체에서도 토큰 누락 여부를 검사했습니다.
- SELECT 역할의 테이블 권한을 RAG 테이블로 한정했습니다. 서버 시작 시 쓰기 권한이 있으면 거부합니다.
- 공유 DB 환경을 실제 Spring Boot/Flyway 구조에 맞췄고 로컬 Alembic과 동시 적용하지 않도록 문서화했습니다.

`ripwire-change-check`로 호출 관계·린트·테스트 영향을 확인했습니다. 최초 저장소여서 HEAD 기반 변경 이력은 없으므로 대상 파일을 명시한 검토를 사용했습니다. 도구가 가리킨 세 테스트 파일은 pytest로 실행했습니다. 정적 분석이 테스트 연결을 찾지 못한 CLI·원본 프로파일·실데이터 검증 스크립트는 실제 명령 실행으로 확인했습니다. 이름 유사성 두 건(release/releases, digest/ingest)은 의미가 다른 명명이며 기능 결함은 아니었습니다. invoke의 연결 수와 publish_context의 인자 수는 검토 대상이었고, 공개 호출 경계/Backend 필드 검증을 유지하면서 테스트로 확인했습니다. 정적 도구 결과만으로 전체 안전성을 보장하지 않습니다.
